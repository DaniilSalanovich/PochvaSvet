# План вайбкодинга: этапы и готовые промпты

Документ для человека, который ведёт разработку с ИИ-агентом (Claude Code, Cursor, Windsurf и т. п.).
Каждый этап — одна сессия агента и один pull request. Промпт копируется целиком; агент сам читает
указанные документы. Правила для агента лежат в `CLAUDE.md` (он же `AGENTS.md`) и подхватываются автоматически.

## 1. Как работать

1. **Один этап — одна ветка — один PR.** Не просите агента сделать «всё v1» за раз.
2. **Сначала план.** Первое сообщение этапа — промпт ниже; агент отвечает планом (файлы, шаги, тесты).
   Проверьте план и только потом скажите «делай».
3. **Тесты — критерий готовности.** Этап закрыт, когда зелёные `pytest`, `ruff`, `mypy` и
   `tools/compare_engines.py`, и вы прошли ручную проверку из раздела этапа.
4. **Проверяйте в живом боте.** Заведите второго, тестового бота у @BotFather и отдельный `.env.dev`.
5. **Агроном проверяет правила, не код.** Любые изменения `rules.json` — отдельным PR с подписью агронома.
6. **Если агент «поплыл»** (переписывает несвязанные файлы, придумывает дозы, ломает тесты):
   остановите, откатите (`git restore .`), сузьте задачу и укажите конкретные файлы.

### Короткий шаблон собственного промпта

```text
Контекст: проект ПочваСвет, см. CLAUDE.md и docs/<нужные файлы>.
Задача: <одно конкретное изменение>.
Ограничения: не трогай <файлы>; агрономические числа только из rules/rules.json.
Готово, когда: <тесты/поведение>.
Сначала покажи план, код — после моего ответа.
```

## 2. Этап 0. Подготовка (вручную, без агента)

- [ ] Установить Python 3.12, Node.js 20+, Docker, Git; создать репозиторий из этой папки.
- [ ] Создать двух ботов у @BotFather: рабочий и тестовый; токены — в `.env` и `.env.dev` (по образцу `.env.example`).
- [ ] Проверить MVP: `cd mvp && pip install -r requirements.txt && python test_engine.py && python test_screens.py && python compare_engines.py`, затем `BOT_TOKEN=... python bot.py` и пройти мастер в Telegram.
- [ ] Выложить `mvp/webapp/index.html` на GitHub Pages, прописать адрес в `WEBAPP_URL`.
