# Движок рекомендаций

Эталонная реализация — `mvp/engine.py` (Python) и `mvp/webapp/engine.js` (JavaScript); они совпадают
на 5000 случайных наборах (`mvp/compare_engines.py`). При переносе в `app/core/engine.py` поведение
**не меняется**; новые функции (раздел 6) добавляются отдельно. Любое изменение логики делается
одновременно в Python и JS, после чего `compare_engines` обязан пройти.

## 1. Вход и выход

```python
build_report(answers: dict[str, str], month: int | None = None) -> Report
```

`answers` — ответы мастера: ключи из `rules.json → questions[].id`, значения — id уровня или опции.
Отсутствующий ключ = тест не делали. `area` — строка с числом м² (`"600"`), `"0"` — не считать.
`month` — текущий месяц 1–12 (для сочетания К8).

## 2. Алгоритм

1. **Контекст.** `ctx = answers` + `org` (итог органики, п. 3) + `month` + `_all_green`.
2. **Сигнал уровня.** `light = level.light`; затем первое сработавшее правило из `level.light_rules`
   (условие проверяется по `ctx`) заменяет его.
3. **Органика.** Сигналы введённых признаков `org_color`, `org_foam`, `org_worms`:
   один признак → его сигнал; ≥ 2 красных → `red`; ≥ 2 зелёных и 0 красных → `green`; иначе `yellow`.
4. **`_all_green`.** Истина, если введено ≥ 3 показателей (pH, карбонаты, N, P, K, итог органики)
   и все они зелёные.
5. **Карточки** в порядке `ph, carb, n, p, k`, затем органика. Каждая: название теста, заголовок уровня,
   сигнал (п. 2), смысл, действия, строки доз (п. 4 ниже).
6. **Сочетания.** Все `combos`, у которых `when` выполняется на `ctx`; их сигнал — с учётом
   `light_rules`. Сортировка: `priority` по возрастанию, затем сигнал (красный выше), затем порядок в файле.
7. **Итог по полю** — худший сигнал среди карточек и сочетаний, кроме К18.
8. **План** и **«не покупать»** — п. 5.
9. **Предупреждения:** калий при `manure = yes`; «не введён ни один результат».

### Проверка условия `when`

Все ключи — через И. Значение-список — через ИЛИ (`ctx[key] in list`). `any` — хотя бы одно из
вложенных условий. `all_green` — сравнение с `_all_green`. Ключ, которого нет в `ctx`, не совпадает
ни с одним значением.

## 3. Дозы

| Тест | Правило | Удобрение для пересчёта |
| --- | --- | --- |
| pH | `level.lime[texture]` т/га, если: есть `lime`, нет шипения (`carb1/carb2`), известна почва; для `ph4` — не для картофеля | Доломитовая мука; г/м² = т/га × 100; кг на участок = середина × площадь / 10 |
| N | `n_mode = full` → `n_full[crop].range`; `minus_reserve` → `range − reserve` (не меньше 0); `none` → «Не вносить» | `default_fertilizer.N` |
| P, K | `level.dose[crop]`; верхняя граница 0 → «Не вносить» | `default_fertilizer.P`; для K — по культуре |

Пересчёт: `кг/га удобрения = д. в. × 100 / pct`; `г/м² = кг/га / 10`; на участок — по середине диапазона:
`кг = (lo + hi)/2/10 × площадь_м² / 1000`, округление до 0,1.

**Округление** — «половина вверх» (`Decimal ROUND_HALF_UP` в Python, `Math.round` с экспонентой в JS).
**Формат чисел** — целые без дробной части, иначе одна цифра после запятой; диапазон `a–b` (en dash),
одинаковые концы — одно число.

## 4. Тексты строк доз (точные шаблоны)

```
Доломитовая мука: {lo–hi} т/га ({lo*100–hi*100} г/м²)
На ваш участок ≈ {кг} кг
Доза: {lo–hi} (азот, кг N/га | фосфор, кг P₂O₅/га | калий, кг K₂O/га)
{Удобрение}: {кг/га} кг/га ({г/м²} г/м²)
На ваш участок ≈ {кг} кг
{note}
Не вносить
```

## 5. План и «не покупать»

План — по порядку, только применимые пункты:

1. `ph ∈ {ph1, ph2}` и нет шипения → известкование этой осенью;
2. сигнал N красный → полная доза азота;
3. сигнал P красный → полная доза фосфора, локально на кислой почве;
4. сигнал K красный → полная доза калия;
5. `ph = ph3` и нет шипения → известкование в течение 1–2 лет;
6. `n = n2` → уменьшенная доза азота;
7. сигнал P жёлтый и не `p6` → фосфор по группе;
8. сигнал K жёлтый и не `k6` → калий по группе;
9. органика красная или жёлтая → навоз, компост, сидераты;
10. ничего из перечисленного → «Срочных действий нет».

«Не покупать»: известь — при `ph5`, `ph6`, шипении или `ph4` не на суглинке; фосфор — при `p5`
(кроме стартовой дозы), `p6`; калий — при `k6` или `k5` для зерновых; азот на ближайшую подкормку —
при `n3`, `n4`.

## 6. Новое в v1: план напоминаний

```python
plan_reminders(report: Report, answers: dict, field: Field, today: date, tz: str) -> list[ReminderDraft]
```

Чистая функция в `app/core/reminders_plan.py`. Время отправки — 09:00 в часовом поясе пользователя.
«Ближайшее 15 сентября» = 15.09 текущего года, если сегодня раньше 15.09, иначе следующего;
если сегодня между 01.09 и 31.10 — через 3 дня.

| Код | Условие | Когда | Текст (шаблон) |
| --- | --- | --- | --- |
| `lime` | есть строка доз извести | ближайшее 15.09 (для картофеля с `ph3` — после уборки, тоже 15.09) | «{поле}: пора известковать. {строка дозы}. Заделать при вспашке или перекопке.» |
| `n_apply` | `n ∈ {n1, n2}`, месяц 3–6 | через 2 дня | «{поле}: внести азот — {строка удобрения}.» |
| `n_retest` | сработало К8 | через 21 день | «{поле}: повторите нитратный тест — решим, нужна ли остальная треть азота.» |
| `k_retest` | сработало К18 | через 21 день | «{поле}: повторите тест на калий — после навоза результат был завышен.» |
| `k_spring` | K красный/жёлтый, почва `sand`/`sandy_loam` | ближайшее 10.04 | «{поле}: внесите калий весной — {строка удобрения}.» |
| `pk_autumn` | доза P или K > 0, почва `loam` | ближайшее 20.09 | «{поле}: основное внесение фосфора и калия под вспашку.» |
| `n_test` | всегда для поля | ближайшее 01.04 | «{поле}: весенний нитратный тест перед посевом.» |
| `pk_retest` | P или K красный → через 1 год, иначе через 2 года | 15.09 года X | «{поле}: пора повторить тесты на фосфор и калий.» |
| `ph_retest` | был `lime` → через 1 год; иначе через 3 года | 15.09 года X | «{поле}: проверьте кислотность.» |
| `org_retest` | органика введена | через 3 года, 15.09 | «{поле}: оцените органику — цвет, пена, черви.» |

Повторное создание напоминаний для того же поля заменяет ещё не отправленные с теми же кодами
(статус `cancelled`), дубли исключены уникальным ключом `(field_id, code, due_at)`.

## 7. Новое в v1: сравнение с прошлым разбором

```python
diff_analyses(prev_answers: dict, cur_answers: dict) -> list[DiffItem]  # test, prev_level, cur_level, arrow
```

Порядок уровней — как в `rules.json`. Для pH, P, K, органики «лучше» = ближе к зелёному сигналу текущей
почвы и культуры; стрелка ↑ — сигнал стал лучше, ↓ — хуже, = — без изменений; тест, отсутствующий
в одном из разборов, не показывается.

## 8. Свойства, которые проверяют тесты

1. Детерминизм: одинаковый вход → одинаковый отчёт.
2. Итог ≥ сигнала любой карточки и любого сочетания, кроме К18.
3. Все дозы ≥ 0; при `carb ∈ {carb1, carb2}` нет строки извести.
4. Каждое сочетание достижимо хотя бы на одном входе (случайный перебор 3000 входов).
5. Python и JS совпадают на 5000 случайных входах.
6. Сочетания и уровни в `when` ссылаются только на существующие id (`test_rules_consistency`).
7. `rules.json` проходит `rules.schema.json`.
