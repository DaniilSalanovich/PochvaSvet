# Безопасность и персональные данные

Документ задаёт технические требования. Юридические формулировки (текст согласия, политика
обработки, трансграничная передача) перед запуском проверяет юрист проекта на соответствие
Закону Республики Беларусь «О защите персональных данных» № 99-З и разъяснениям уполномоченного органа.

## 1. Какие данные храним

| Данные | Персональные? | Зачем | Срок хранения |
| --- | --- | --- | --- |
| Telegram ID, имя из профиля | Да | Работа бота | Пока пользователь не удалит данные или 24 мес. неактивности |
| Район, тип хозяйства | Да (в связке с ID) | Агроном района, статистика | То же |
| Поля: название, площадь, почва, культура | Да (в связке с ID) | Рекомендации, дневник | То же |
| Геоточка поля | Да | Прогноз погоды | То же; можно не указывать |
| Ответы тестов, отчёты, дневник | Да (в связке с ID) | Дневник, история | То же |
| Фото тестов | Да | Распознавание; датасет — только с отдельным согласием | Без согласия на датасет — не сохраняются (только `tg_file_id`); с согласием — до отзыва |
| Обращения к агроному | Да | Консультация | 24 мес. |
| Обезличенная статистика по районам | Нет | Карта почв для райуправлений и НАН | Бессрочно |

Не собираем: телефон, ФИО полностью, паспортные данные, платёжные данные.

## 2. Согласие

Экран при первом использовании функций, сохраняющих данные:

```
Чтобы сохранять ваши поля, результаты и напоминания, нам нужно ваше согласие на обработку
персональных данных: имени в Telegram, района, данных о полях и результатах тестов.
Данные используются только для работы бота и консультаций агронома вашего района.
Вы можете удалить все данные в любой момент командой /privacy.
[Согласен] [Позже] [Подробнее]
```

Отдельные согласия (по умолчанию «нет»), меняются в `/privacy`:

- обезличенная статистика по району (`stats_consent`);
- сохранение фото тестов для улучшения распознавания (`dataset_consent`).

Факт и время каждого согласия и отзыва пишутся в `users` (и в журнал `consent_log` — v2).

## 3. Права пользователя (`/privacy`)

- Посмотреть, что хранится (сводка: число полей, разборов, записей, фото, согласия).
- Выгрузить свои данные в JSON (v2).
- Отозвать любое согласие.
- Удалить всё: двухшаговое подтверждение → каскадное удаление из БД + удаление файлов фото +
  удаление FSM-ключей Redis. Выполняется сразу; в бэкапах данные исчезают по истечении срока хранения бэкапов (30 дней) — это указывается в тексте.

## 4. Технические требования

| Тема | Требование |
| --- | --- |
| Секреты | Только переменные окружения; `.env` в `.gitignore`; токен бота не печатается в логах |
| Логи | Без Telegram ID (только `user_hash = sha256(salt + tg_id)[:16]`), без текстов сообщений, без координат, без содержимого фото |
| Доступ к БД | Отдельный пользователь БД для приложения без прав суперпользователя; порт PostgreSQL не публикуется наружу |
| Хранилище | Диск сервера с шифрованием (LUKS или шифрование провайдера); бэкапы шифруются (`age` или `gpg`) |
| Ввод | Весь пользовательский текст экранируется перед отправкой в HTML-режиме; длины ограничены (название поля 40, вопрос агроному 1500, заметка 2000) |
| Файлы | Принимаем только JPEG/PNG/HEIC до 20 МБ; декодирование с ограничением 40 Мпикс; EXIF удаляется перед сохранением |
| Callback | Аргументы callback_data проверяются: поле, напоминание, тикет должны принадлежать текущему пользователю, иначе «Не найдено» |
| Админ-команды | Проверка `role = admin` или `tg_id in ADMIN_IDS` в middleware; все действия админа пишутся в лог |
| Агроном | Видит только обращения своего района и обезличенную статистику; ответы идут только через бота |
| Мини-приложение (v2) | Проверка `initData`: HMAC-SHA256, секрет = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN); `auth_date` не старше 24 ч; без проверки запрос отклоняется (401) |
| LLM (v3) | В запрос — только фото без EXIF и обезличенный контекст (культура, месяц, уровни тестов) |
| Ограничение частоты | Не больше 30 действий в минуту на пользователя (middleware с Redis); фото тестов — 20 в час |
| Обновления | Зависимости фиксируются в lock-файле; Dependabot или `pip-audit` в CI раз в неделю |

## 5. Хостинг и трансграничная передача

Хранение данных пользователей из Беларуси за рубежом требует соблюдения условий трансграничной
передачи по закону № 99-З. Варианты для решения юристом (открытый вопрос № 4 в ТЗ):

1. VPS у провайдера в Беларуси — самый простой путь с точки зрения закона.
2. Зарубежный VPS — только после юридической оценки и с соответствующим текстом согласия.

Внешние API (Open-Meteo, LLM) получают только обезличенные данные: координаты поля для погоды
округляются до 0,1° (≈ 10 км) и не связываются с пользователем.

## 6. Инциденты

При утечке или подозрении: отозвать токен бота у @BotFather, сменить пароли БД и ключи API,
оценить объём затронутых данных, уведомить уполномоченный орган и пользователей в сроки и порядке,
установленные законодательством (уточняет юрист). Контакт ответственного за защиту данных указывается в `/privacy`.
