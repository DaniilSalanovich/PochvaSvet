# ПочваСвет — правила для ИИ-агента

Telegram-бот для фермеров Беларуси: по результатам дешёвых тестов почвы выдаёт сигнал светофора
(🟢 🟡 🔴), дозы удобрений и план действий. Пользователь — фермер без агрономического образования.

## Где что лежит

- Требования: `docs/01_TZ.md` (ID требований FR-x.y, NFR-x). Предметная справка: `docs/00_domain.md`.
- Сценарии и `callback_data`: `docs/02_user_flows.md`. Архитектура и структура папок: `docs/03_architecture.md`.
- Данные: `docs/04_data_model.md`. Движок: `docs/05_rules_engine.md`. Фото тестов: `docs/06_photo_recognition.md`.
- Фото растений: `docs/07_plant_photos_llm.md`. Тесты и приёмка: `docs/08_testing.md`.
- Безопасность: `docs/09_security_privacy.md`. Тексты: `docs/10_copy_guide.md`. Этапы: `docs/11_vibecoding_plan.md`.
- Работающий MVP-эталон: `mvp/` (не редактировать; удаляется после этапа 1).

Перед задачей прочитай документы, указанные в промпте этапа, и раздел ТЗ с нужными FR.

## Жёсткие правила

1. **Никаких агрономических чисел в коде.** Дозы, пороги, тексты рекомендаций — только из `rules/rules.json`.
   Не хватает числа — остановись и спроси; не придумывай.
2. **Движок — в двух копиях.** Логика `app/core/engine.py` повторена в `webapp/engine.js`. Меняешь одну —
   меняешь вторую и запускаешь `python tools/compare_engines.py` (должно быть 5000 из 5000).
3. **Ядро чистое.** `app/core/` не импортирует aiogram, БД, сеть, файловую систему (кроме загрузки правил в `rules.py`).
4. **Экраны отдельно от Telegram.** `app/screens/*` возвращают `Screen(text, buttons)`; обработчики только
   получают данные, вызывают экран и отправляют.
5. **Ограничения Telegram:** `callback_data` ≤ 64 байт по схеме `docs/02_user_flows.md` (раздел 10);
   сообщение ≤ 4096 символов (делить по 3800); `parse_mode=HTML`, весь пользовательский текст —
   через `html.escape`; разрешены теги `<b>`, `<i>`, `<code>`.
6. **Чужие данные.** Любой id из `callback_data` проверяй на принадлежность текущему пользователю.
7. **Логи без персональных данных:** не логируй Telegram ID (только `user_hash`), тексты сообщений, координаты.
8. **Секреты** только из переменных окружения через `app/config.py`.
9. **Тексты для пользователя** — на русском, по `docs/10_copy_guide.md`. Дисклеймер из `rules.json → meta.disclaimer` в конце каждого отчёта не удалять.
10. **Распознавание фото — без нейросетей и LLM** (OpenCV, детерминированно). LLM — только для фото растений (v3), и её текст пользователю не показывается напрямую.
11. **Время:** храним UTC (`timestamptz`), показываем в часовом поясе пользователя (по умолчанию `Europe/Minsk`).
12. **Долгие операции** (распознавание, LLM, PDF) — не в event loop: `run_in_executor` с таймаутом.

## Как работать

- Сначала план: какие файлы создашь/изменишь, какие тесты добавишь. Код — после подтверждения.
- Меняй только то, что относится к задаче. Не переформатируй несвязанные файлы.
- Каждое новое поведение — с тестом. Новый экран — попадает в обход экранов `tests/screens`.
- Перед завершением запусти и приложи вывод:

```bash
ruff check . && ruff format --check .
mypy app/core app/screens
pytest -q
python tools/compare_engines.py
```

- В описании PR: какие FR закрыты, какие AT из `docs/08_testing.md` проверены, что осталось открытым.

## Стиль кода

Python 3.12, типы везде, `dataclass(slots=True)` для структур ядра, `Literal` для перечислений
(`Light = Literal["green","yellow","red"]`). Имена — по-английски, строки для пользователя — по-русски.
Асинхронный код — `async`/`await`, SQLAlchemy 2.0 стиль (`select()`), без глобальных сессий.
Функции до ~50 строк; модуль — одна ответственность.
